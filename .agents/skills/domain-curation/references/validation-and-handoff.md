# Validation and handoff

Use after extraction to check applicability and decide what to deliver. Criteria and cases are chosen before writing the guidance so the prose cannot define its own success.

## Evidence ladder, not a certification ladder

- **Source reconciliation:** claims have locators, origin lineage and explicit limits; no task performance implied.
- **Desk walkthrough:** trace a supplied or synthetic case against the guidance. Can reveal missing steps; no real task attempt implied.
- **Executed practice:** an authorized actor performs a bounded task with observed results, safely and within resources. State who/what was tested and what was not.
- **Practitioner feedback:** a real qualified person checks the interpretation or application under stated conditions. Attribution/consent required; one person's approval is not universal validation.

These evidence types can complement each other. Never promote a desk exercise to execution or repeated retellings to independent corroboration. An agent's role-play is neither practitioner feedback nor proof of expertise.

## Two-case check

1. **Representative case:** the agreed learning task with explicit expected outcome. Can the learner find prerequisites, choose an action, recognize failure and know when to escalate?
2. **Boundary case:** change a condition on which the advice depends. Does the guidance prevent the wrong transfer? Include a plausible failure or costly exception.

Use only authorized, safe tasks. If execution is unavailable, walkthrough the available cases and label the result provisional. If even case evidence is absent, identify the next check rather than inventing outcomes. For high-stakes domains, obtain relevant qualified review before operational use; consultation does not itself authorize execution.

## Check receipt

Record in the brief:

- Scope and success/failure criteria fixed beforehand.
- Case/input and evidence type; planned versus actually performed.
- Observable result or walkthrough conclusion, not just “passed.”
- Failed/ambiguous assumptions, corrections and unresolved branches.
- Source independence and access limits; next discriminating check.

### Disconfirming examples (synthetic, not executed domain pilots)

| Input | Required result |
|---|---|
| Five posts repeat one person's claim | One origin, not five independent confirmations; consequential advice stays provisional |
| Learner has documents but cannot interview anyone | Curate documents, label practitioner gap; no fabricated testimony |
| No retrieval tool and no supplied evidence | Scoped acquisition plan; no unsupported factual playbook |
| A walkthrough handles one easy case but no actual task was tried | Useful draft brief, not demonstrated competence or packaging-ready workflow |
| Senior practitioner advises a shortcut requiring unavailable equipment | Keep equipment prerequisite; reject transfer to the learner's setting |

## Packaging decision

Prefer the smallest brief/checklist unless all are true:

1. A recurring task has a reusable workflow and benefits beyond a one-off note.
2. Critical guidance has traceable, appropriately corroborated evidence with disagreements and conditions intact; unsupported critical branches remain blocked.
3. An actual, authorized task attempt has informed the workflow's limits; failures/counterexamples are recorded. Desk simulations alone do not qualify.
4. Reader inputs, authority, capability-absence paths, outputs and stops are clear enough for another reader without the chat.

When met and authoring is authorized, hand off to `skill-author` with task scope, conditional cards, evidence ledger, attempt receipt, failure/boundary cases and unresolved branches. Ask it to extend an existing skill first; a new artifact begins as a prototype with audit criteria. Otherwise state which condition is unmet and the next learning action. This gate is about **curated domain knowledge**, not a ban on authoring a methodology prototype before its first field use.

## Reader/capability checks for the curator

Before delivery, read the brief without chat context. Can its reader find sources and act within limits?

- Native retrieval available: use only permitted reading, record actual locators/results.
- Authorized integration available: same evidence contract; no provider-specific prerequisite.
- Neither available: supplied material remains sufficient for bounded synthesis; absent material yields an acquisition plan.

These are portability checks. Label hypothetical walkthroughs separately from executed evidence.
