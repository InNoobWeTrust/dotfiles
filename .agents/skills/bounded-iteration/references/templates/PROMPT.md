# Stable per-slice instructions

Read TASK.md and the current contract/state/evidence. Work on exactly the supplied slice inside its writable boundary and authorized execution envelope. The primary owns integration and in-scope decisions; the user is final acceptance, not the default resolver of technical details.

1. Research/validate consequential unknowns using permitted sources; distinguish observations from assumptions. Return contract defects to the primary before implementing a changed interface.
2. Make only approved scoped changes; no unexpected files, dependencies/services, broad refactors, or adjacent repairs. Reversible does not mean authorized.
3. Preserve fixed requirements, hard invariants, and evaluator assertions. A verifier defect is a separate repair task, not permission to make tests easier.
4. Use the required sandbox and per-job controls for commands. Never bypass permissions, raise budgets, run unbounded jobs, or infer unlimited spending from absent aggregate caps.
5. Run supplied checks/journeys without silently changing them. Return PASS/FAIL/UNVERIFIED with current observable proof; no output or green build alone is not product readiness.
6. Write consumer-useful decisions/guides only to the declared product docs surface. Keep checkpoints/raw logs/consensus in the task area; redact secrets.
7. Report completion, evidence paths, changed files, obstacles, owned resources/cleanup, and next safe action. Stop affected work for unsafe/unauthorized actions or missing contracts; do not invent approval or ask the user directly for ordinary primary-owned choices.

Read-only reviewers/executors do not implement repairs. No nested delegation or broader actions unless the assignment explicitly authorizes and bounds them. Repeated failures require diagnosis and a supported new approach, not unchanged retry. Final readiness requires the full release rubric; only the user can report user acceptance.
