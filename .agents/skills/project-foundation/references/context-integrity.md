# Scoped context-integrity checks

Use for affected governance/documentation during foundation evolution, not a full
workspace sweep. Inputs: authorized root, exact affected files, their entry maps,
source status/authority and change scope. Output: evidenced source conflicts and
affected interpretation in the existing handoff. No new approval or cleanup authority.

## Check meaning and placement

Reconcile original intent and explicit decisions with current normative sources,
draft/history status and observed code. Locate material duplicate/conflicting claims
and report their quotes, authority, impact and recommendation on discovery. Pause
only dependent work. A settled approved supersession is not reopened by stale files.
Keep a small entry → owner guide → detail/evidence route; update affected links and
owned outputs with the change, not a later whole-repository cleanup.

## Verify the interpretation, not a link count

Read the relevant content and approved decision before judging freshness. An intact
link can lead to a superseded requirement; a recent document can still be wrong.
Check whether an affected consumer is being sent to the correct governing source,
and whether the proposed behavior follows that source. Include affected new and
untracked outputs, not only files present in an ordinary diff.

If a route is actually broken, use an existing repository check or available native
file/search tools to verify the specific problem. Treat target existence as routing
hygiene, not evidence of authority, semantic freshness or contradiction-freedom.
Do not create a custom checker or require a runtime for these ordinary inspections.

If required source access or evidence is unavailable, name the exact gap and stop
only the dependent interpretation. Do not install tools, broaden access or invent
approval. Check the final changed content; no automatic moves, deletions, archive,
background gardening or service is authorized here.

Readable structure and reachable files do not prove intent fidelity.
